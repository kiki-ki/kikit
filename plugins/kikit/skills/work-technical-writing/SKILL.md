# work-technical-writing

疲れたエンジニアが一度読んで分かる文章を書く。

このファイルには言語によらない規則を置き、それ以外の規則は `references/` に分けている。

## 1. 書く前に決める

- 読み手と目的: 誰が読み、読み終えたら何を判断し、何をできるようになればよいかを、一文で言える状態にする。言えなければ、書く前に材料を集めるかユーザーに聞く
- 文書の種類: 1 つの文書は 1 つの種類にする。混ざったら分けてリンクする
  - 手順: 目的を達成するための操作だけを書く。背景は書かずリンクする
  - リファレンス: 事実・選択肢・制約を、説明する対象と同じ構造で淡々と書く
  - 解説: なぜそうなっているか（設計判断、経緯、制約、別案）を書く。意見を書いてよいのはここだけ
  - チュートリアル: 手を動かしながら学ぶ。各ステップで何が見えるはずかを書く
- 読み手に見えているもの: 読み手はこのセッションの会話も調べた過程も見ていない。セッション中に生まれた呼び名、「先ほどの方針」、試して捨てた案の経緯は、そのままでは通じない。読み手に要るものだけを、読み手の手元にある情報で分かるように書く
- 書かないこと: 読み手が自力で補える前提、一度しか出てこない固有名、判断に関わらない数字（時刻、件数、割合など）は、最初から書かない
- 細かい識別子: バージョン、コミットのハッシュ、行番号は、読み手がその値を使って再現したり、探したりするときだけ書く。参照先を示すだけなら、リンクか名前で足りる

## 2. 組み立てる

- 文書・節・段落・文のどの単位でも結論を先に書き、結論 → 詳細 → 背景の順にする。見出しだけを上から読んで主旨が伝わるようにする
- よくある場合を先に書き、例外や失敗したときの挙動は後ろに回す
- 長さは中身に合わせ、形だけの節（「概要」「まとめ」「今後の課題」）や定型文で水増ししない
- 同じ情報は 1 か所にだけ書く。同じ主張、列挙、説明を、見出しや導入の文も含めて 2 か所以上に書かない。本文の中で 2 か所目が要るときは、最初の場所を指す。見出し、冒頭の説明、箇条書きや表の直前の導入文では、中に並ぶものの名前も数も書かず、まとめて呼ぶ名前で書く。「認証は OAuth、API キー、セッションの 3 つの方式に対応する」ではなく「認証の方式と、その選び方を示す」と書く。表の導入文なら、列の名前を並べずに「方式ごとの違いを比べる」と書く。項目や列を足しても、見出しと導入の文は直さなくて済むようにする。ほかの文書にすでにある説明は、書き写さずリンクする。同じリンク先へのリンクは、読み手が最も使う 1 か所だけに置く
- 書き方は、[references/formats.md](references/formats.md) に従って決める

## 3. 文を書く

- 一文に一つのことだけを書く。二つのことを言っている文は切る
- 誰が何をするかを書く。「〜が確認された」ではなく「CI が〜を確かめる」。受け身は、行為者が分からないときか関係ないときだけ使う
- 同じものは、文書の最後まで同じ名前で呼ぶ。言い換えると、別のものがあるように読める
- 普段使う言葉で書く。造語や比喩は避け、使うときは初めて出るところで意味を書く
- コード、パス、コマンド、フラグは、実物の名前を言い換えない
- 言い切るのは、材料（diff、メモ、実行結果、原文）で確かめたことだけにする。確かめていない挙動や影響、推定、仮定は、その不確実さが分かる形で書く
- 因果を書くときは、なぜそうなるかを一文で添える
- 「A ではない」と否定するときは、否定する内容をはっきり書き、根拠を一文添える。二重否定は使わず、肯定で書き直す
- 「必ず」「すべて」は、本当にそうだと確かめたときだけ使う

## 4. 見直す

書き終えたら、次の順に点検して直す。

1. [references/ai-tells.md](references/ai-tells.md) の項目と、上から順に照らし合わせる
2. 「2. 組み立てる」で選んだ書き方が、`references/formats.md` に合っているかを確かめる
3. 日本語なら [references/japanese-sentences.md](references/japanese-sentences.md) と照らし合わせる
4. 見出しと各段落の最初の文だけを上から読み、「1. 書く前に決める」で決めた目的を果たせるかを確かめる。足りなければ足し、消しても読み手が困らない文は消す

規則に従うとかえって読みにくくなる文は、別の方法で直すか、そのままにする。規則は読み手のためにある。

## 既存の文章を直すとき

- 原文にない事実・理由・数値を足さない。もっともらしい推測でも書かない
- 必要なのに欠けている情報は【要記入】として残すか、ユーザーに聞く
- 直す必要のない文は言い換えない。差分を読む人の手間が増える
- 同じ直し方を、全体へ機械的に広げない。直して読み手が得をする箇所だけを直す
- 意味を変えずに、1〜4 の節に沿って直す
