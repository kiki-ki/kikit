# principle-sequence-verifiable-units

作業を、確かめられる状態で終わる小さな単位の列にする。今の単位のチェックが通るまで次に進まない。壊れたところは壊した単位で見つければすぐ特定できる。まとめて進めた後で見つけると原因が埋もれ、しかも壊れた土台の上に積み上げてしまっている。

## 進め方

- 始める前に最新のメインブランチへ rebase し、正しい基準と比べられるようにする
- 似た編集を繰り返すときは、1 つ変えるたびに確かめる。正常な状態から 1 つ変え、チェックを実行し、通ってから次へ進む
- 道具で編集していてチェックが安くても、毎回実行する

## 届け方

コミットと PR は、作業の正しさが分かる順に積む。各コミットは単独で成り立つようにする。順番の例は次のとおり。

- 失敗するテストを先に置き、その上に修正を積む（いちばんよくある形）
- 形を変える前に、不要なものを消す
- 変更の前に、基準値を取る
- 機能の前に、足場を作る

各チェックを本物にするのは [principle-prove-it-works](../principle-prove-it-works/SKILL.md)、チェックを安くするのは [principle-build-the-lever](../principle-build-the-lever/SKILL.md) の役割だ。

完了を報告する前に、Skill ツールで `kikit:principle-prove-it-works` を呼び、その確かめ方に従う。
