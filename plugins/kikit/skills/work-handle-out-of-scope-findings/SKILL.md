# work-handle-out-of-scope-findings

スコープ外の発見は、今の変更に混ぜず、忘れもしない。混ぜると 1 コミットに複数の変更が入り、レビュアーは本筋の変更と別件を切り分けて読むことになる。捨て置くと、気づいた文脈ごと失われる。

## 1. スコープ内かを決める

今のタスクを止めるものは、スコープ内として扱う。それを直さないと、今のタスクを完了できないか、完了を確かめられないものだ。本筋の変更とは別のコミットにして、先に直す。

それ以外は、どれほど小さくても今の変更に入れない。typo の 1 文字でも同じにする。

## 2. 記録して本筋に戻る

気づいた時点で、次のことを 1〜2 行で記録し、調べ込まずに本筋へ戻る。記録は、タスクリストなど、セッションの終わりで見返せる場所へ置く。memory には置かない。

- 場所: `file:line`、コマンド、URL
- 何が問題か
- 根拠: 確かめた事実か、推測か。推測なら推測と書く

## 3. 最後に一覧を出す

タスクの報告の後に、記録した発見を一覧にして、それぞれに処理の案を 1 つ付ける。ユーザーが案を選ぶまで、どれにも手を付けない。

- 別ブランチ・別 PR で直す: 直し方がはっきりしていて、小さいもの。今の作業と並行して進めるなら、ワークツリーを分ける
- issue にする: 調査が要るもの、ほかの人が着手するもの。起票は [work-create-github-issue](../work-create-github-issue/SKILL.md) に従う
- 捨てる: 影響が小さいもの、直すと今の挙動に頼っている人が困るもの。捨てる理由を書く

push、PR の作成、issue の起票のように外に書き込む操作は、ユーザーの合意を取ってから行う。
